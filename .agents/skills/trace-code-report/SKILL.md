# 変数の変化を追うレポート

実際のコードと具体的な入力を根拠に、「どの値を読み、どの条件で、何が変わったか」を説明する。特定の課題名や変数名に限定しない。標準の成果物は会話内の日本語レポートとし、ファイル形式・保存先の指定があればそれに従う。

## 対象を確かめる

- スキル名や「ステップごと」という指定がなくても、コードの説明依頼ならこの手順を使う。追跡する変数の指定がなければ、結果を理解するために重要な変数を選ぶ。説明の詳しさは依頼に合わせ、短い説明を求められた場合は主要な変化に絞る。
- 対象ファイル・関数・追跡する変数を、依頼と会話の文脈から特定する。入力の指定がなければ既存の実行例を使い、レポート内に明示する。例がないときは、主要な分岐がわかる小さな入力を選び「説明用の入力」と記す。
- 適用されるAGENTS.mdと、必要な範囲のコード・テスト・課題資料を読む。課題資料とコードに差があれば、どちらを説明しているか明示する。
- 説明だけの依頼では元のコードを変更しない。途中経過を表示するプログラムの作成・変更まで求められた場合のみ、指定された範囲で実装する。

## 値の変化を確かめる

- 可能なら対象を実行して追跡する。元の処理を観測できるデバッガーや一時的なトレースを使い、説明用に書き直した別のアルゴリズムだけを検証根拠にしない。
- 実行前に入出力や副作用を確認する。実行できない場合は静的に追跡し、「コードを読んで追跡した結果」と記す。未実行の値を実行確認済みと表現しない。
- 初期状態をステップ0とする。各行の実行・変数更新・ループ1回などから、理解しやすい単位を選ぶ。表の値が処理前か処理後かを明記する。
- ループ1回で複数の重要な更新がある場合は、その中を小さなステップに分ける。分岐により値が変わらない場合も、理由を記録する。ネストしたループや再帰では、添字や呼び出しの深さを添えて順序を区別する。
- リストや辞書などの途中状態は、後の変更で過去の記録が変わらないよう、その時点の文字列または適切なコピーで記録する。
- Pythonの行トレースは通常、その行の実行前に通知される。更新後の値は次のイベント等で観測し、最終反復の更新も取りこぼさない。固定の行番号を他のコードに流用しない。
- 最終状態を戻り値・標準出力と照合する。関連する既存テストがあれば必要に応じて実行し、実行した範囲だけを報告する。説明のためだけにテストや依存ライブラリを追加しない。

## レポートにまとめる

次の要素を、対象に合わせた長さで自然につなげる。

1. **目的と入力**：プログラムが何を求めるか、今回使う入力、追跡する変数の役割を説明する。辞書ならキーと値の意味も示す。
2. **更新の規則**：重要なコードだけを短く引用し、条件が成立するとき・しないときの処理を具体的な値で説明する。
3. **ステップ表**：「ステップ」「現在の入力・添字」「判定と実行する処理」「処理後の変数」を示す。少数の入力は全ステップを載せる。大量の入力は範囲や省略を明示し、全件を示したように扱わない。
4. **つまずきやすい箇所**：表の代表的な1ステップを取り上げ、式を実際の値に置き換えて説明する。初期化の位置、インデント、添字、辞書のキー判定、早期returnなど、対象に関係する点だけを補足する。
5. **最終結果と確認方法**：戻り値と表示内容を区別して示す。件数の合計など、簡単に確かめられる関係があれば添える。実行追跡か静的追跡か、実施したテストと結果を明記する。

構文の言い換えだけで終わらず、値が変わる理由と、保持される値を説明する。識別子・入力・出力は元の表記を維持する。

## 小さな出力例

辞書で回答回数を集計するコードに `['A', 'B', 'A']` を渡す場合：

| ステップ | item | 判定と処理 | 処理後のcounts |
|---|---|---|---|
| 0 | — | 空の辞書を用意 | `{}` |
| 1 | `'A'` | 未登録なのでAを1にする | `{'A': 1}` |
| 2 | `'B'` | 未登録なのでBを1にする | `{'A': 1, 'B': 1}` |
| 3 | `'A'` | 登録済みなのでAを1から2にする | `{'A': 2, 'B': 1}` |

ステップ3では `counts['A'] += 1` により `1 + 1 = 2` になる。Bの回数は1のままである。初期化がループの外にあるため、それまでの回数を保持できる。この表は形式の参考とし、実際の対象コードと入力に合わせて作り直す。
